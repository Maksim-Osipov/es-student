# Занятие 3.1: АЦП, телеметрия и RC-цепь

Реализованы задания 3.1.1–3.1.5 на основе `231-firmware-template`.
Готовая прошивка: [`firmware/311_adc.uf2`](firmware/311_adc.uf2).
Она предназначена для обычной **Raspberry Pi Pico с RP2040**, как в заданиях курса.

## Что подготовлено без платы

- АЦП GP26, температура кристалла, поток телеметрии и управление GP22.
- Оригинальные скрипты курса `check-3-1-1.py` — `check-3-1-3.py`.
- `get_telemetry.py`: приём USB, CSV и график, автономный режим `--plot`.
- `rc.py`: автоматический заряд и разряд, расчёт τ по алгоритму курса, график и отчёт.
- `capture_all.py`: последовательный запуск всех пяти заданий с настоящей платой.
- Пять официальных проверок GitHub Actions и тесты логики на компьютере.

**Платы при разработке не было.** Изначальные `device-3-1-*.log`, `telemetry.csv`,
`rc.csv`, PNG и `rc.log` — воспроизводимые учебные примеры, а не физические измерения.
Логи содержат `порт: SIMULATED` и условный нулевой серийный номер.
Источник CSV указан в `telemetry.meta.json` и `rc.meta.json`; графики имеют подпись
«учебная модель, без платы», `rc.log` содержит `data_source = simulation`.
Зелёные автоматические проверки этих примеров подтверждают код и формат данных.
Проверка реальной схемы выполняется в вузе по шагам ниже.

## Перед посещением вуза

Скопируйте **всю папку `311-adc`**, включая `firmware`, на компьютер, который будет
подключён к плате. Для готового UF2 установка SDK и компилятора не требуется.
Нужен Python 3.10 или новее и библиотеки:

```powershell
cd C:\Repositories\pico\es-student\311-adc
python -m pip install -r requirements.txt
```

Подготовьте Pico RP2040, USB-кабель с передачей данных, резистор **10 кОм**,
электролитический конденсатор **100 мкФ, от 6,3 В**, макетную плату и перемычки.

## В вузе: загрузка и подключение

1. Удерживая BOOTSEL на Pico, подключите её по USB. Отпустите кнопку.
2. Скопируйте `firmware/311_adc.uf2` на появившийся диск `RPI-RP2`.
   Диск исчезнет: плата перезапустится с новой прошивкой.
3. Отключите USB и соберите цепь:

   | Соединение | Вывод Pico |
   | --- | --- |
   | Первый конец резистора 10 кОм | GP22, физическая ножка 29 |
   | Второй конец резистора и плюс конденсатора | GP26, ножка 31 |
   | Минус конденсатора (полоса на корпусе) | AGND, ножка 33 |

   Получается `GP22 → R → GP26 → C → AGND`. Номера ножек считайте по маркировке
   платы или схеме Pico. На GP26 допустимо только 0–3,3 В.
4. Подключите USB обычным образом, без BOOTSEL. Закройте терминалы,
   мониторы порта VS Code и другие программы, которые могут занимать COM-порт.

## Быстрая ручная проверка 3.1.1 и 3.1.2

До сборки RC-цепи можно проверить вход перемычкой. В последовательном терминале
выберите COM-порт Pico, скорость 115200, окончание команды CR или LF.
`info` должен показать `project: 311-adc`.

- GP26 → AGND: `get_voltage` показывает почти 0 В.
- Уберите перемычку с земли, затем GP26 → 3V3(OUT), ножка 36:
  `get_voltage` показывает около 3,3 В. Не соединяйте 3V3 с землёй.
- `get_temp` возвращает температуру кристалла; повторный `get_voltage`
  продолжает читать GP26.

Перед общим прогоном уберите эту перемычку, подключите RC-цепь по таблице и закройте
терминал. При подключённой RC-цепи и выключенном заряде напряжение близко к нулю — это нормально.

## Записать все реальные результаты

Из папки проекта выполните:

```powershell
python capture_all.py
```

Скрипт сам найдёт Pico и выполнит три проверки команд, запишет десять секунд
телеметрии, затем разрядит конденсатор за 5τ и проведёт RC-опыт длительностью 11 секунд.
Для стандартных номиналов этот этап занимает около 16 секунд. Полный прогон занимает
около минуты. Во время записи цепь не трогайте.

Команды отдельных заданий:

```powershell
python check-3-1-1.py
python check-3-1-2.py
python check-3-1-3.py
python get_telemetry.py
python rc.py --r 10 --c 100
```

Если номиналы другие, укажите их: `python capture_all.py --r 4.7 --c 100`.
R задаётся в кОм, C — в мкФ. Допустим R от 1 до 100 кОм и R·C от 0,2 с.

Успешный прогон заменит учебные логи, таблицы и графики настоящими данными.
В JSON появится `"source": "hardware"`, в `rc.log` — `data_source = hardware`.
Для 10 кОм и 100 мкФ обе оценки τ должны оказаться между 0,76 и 1,26 с.
На графике напряжение сначала растёт, затем спадает; две красные точки находятся
в зелёных полосах. При другом номинале диапазон пересчитывается автоматически.

Отправьте результаты:

```powershell
git add 311-adc
git commit -m "Снять измерения 3.1 на Pico и RC-цепи"
git push
```

Пять проверок запустятся автоматически. Пока плата не подключена, повторно строить
графики можно так:

```powershell
python get_telemetry.py --plot telemetry.csv
python rc.py --plot rc.csv
```

## Если что-то не запускается

- **Остаётся диск RPI-RP2:** скопируйте UF2 и переподключите плату без BOOTSEL.
- **Плата не найдена:** проверьте USB-кабель и наличие COM-порта. Для скриптов сбора
  можно явно указать `--port COM5` (номер заменить на свой); общий прогон и скрипты
  курса ищут USB VID/PID `2e8a:000a` автоматически.
- **Доступ к порту запрещён:** закройте остальные программы, использующие его.
- **Нет `tm:`:** проверьте `info`, должна быть прошивка `311-adc`.
- **τ не в диапазоне:** проверьте номиналы, полярность и соединения; перезапустите
  `rc.py --r 10 --c 100` с фактическими номиналами. Автоматически допуск не расширяется.

## Сборка и воспроизведение примеров

Для изменения прошивки нужны Pico SDK, Arm GNU Toolchain, CMake, Make и picotool,
как для предыдущих заданий. Из корня репозитория:

```powershell
cmake -S 311-adc -B 311-adc/build -G "Unix Makefiles" -DCMAKE_BUILD_TYPE=Release
cmake --build 311-adc/build --parallel
```

В Windows Make может потребоваться задать через `-DCMAKE_MAKE_PROGRAM`.
После изменения исходников используйте **новый** `311-adc/build/311_adc.uf2`.
В `firmware/` лежит заранее собранный файл этой версии; его SHA-256 записан рядом.

Программная модель исполняет C-код `platform`, API, протокола и задач, заменяя SDK
моделью АЦП, GPIO и времени. RC-модель идеальная, τ = 1 с, отсчёты квантованы в 12 бит.
Воспроизводить примеры после получения реальных измерений не нужно:

```powershell
cmake -S tests/host -B tests/host/build
cmake --build tests/host/build --config Debug
ctest --test-dir tests/host/build -C Debug --output-on-failure
python tools/generate-adc-examples.py --runtime tests/host/build/Debug/adc_runtime.exe
```

На Linux приложение находится в `tests/host/build/adc_runtime`.
